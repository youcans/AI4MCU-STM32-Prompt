## 1. Project Overview

This repository is the companion code for the book *AI-Driven STM32G4 Development Workflow*. It targets the STM32G4 series of MCUs and demonstrates AI-assisted development using **structured prompts**.

The repository provides three types of **project working directories** — basic peripherals, system architecture, and integrated experiments. Each experiment project is preloaded with the initial files required for development, so readers can enter the corresponding directory and start practicing directly. The repository also includes **reference projects** completed through the full development workflow, along with **hardware documentation** for the NUCLEO-G431RB board, for readers to study and compare.

## 3. Working Directory Description

### 3.1 Project Working Directories

`nucleo-g431rb_basics/`, `nucleo-g431rb_system/`, and `nucleo-g431rb_integrated/` are the **project working directories** for readers to practice the chapters of the book:

- `nucleo-g431rb_basics/`: basic peripheral experiments, covering GPIO, timers, PWM, ADC, DAC, USART, I2C, SPI, interrupts, DMA, RTC, watchdog, Flash, and more;
- `nucleo-g431rb_system/`: system architecture experiments, covering multitask polling, event-driven design, state machines, and FreeRTOS;
- `nucleo-g431rb_integrated/`: integrated experiments, covering hardware co-working applications such as ADC synchronized with PWM triggering.

Each experiment project directory is preloaded with **two basic input files** that serve as the starting point for development:

```text
nucleo-g431rb_basics/
└── GPIO_EXTI/
    ├── GPIO_EXTI.ioc         STM32CubeMX project configuration file
    └── requirements.txt      Project requirements description file
```

- **`.ioc` file**: preconfigured with the peripherals, pins, clocks, and other basic parameters required for the experiment. Readers can open it with STM32CubeMX to generate the initial project without configuring from scratch.
- **`requirements.txt`**: describes the experiment's goals, functional requirements, and hardware information in natural language. It can serve as the project requirements input when executing structured prompts.

### 3.2 Complete Reference Projects

`nucleo-g431rb_completed/` contains projects completed through the full development workflow, for readers to compare against after finishing the experiments on their own.

### 3.3 Hardware Documentation

`nucleo-g431rb_hardware/` provides hardware documentation for the NUCLEO-G431RB board, including datasheets, schematics, user manuals, and BOM files, for reference during development.

## 4. AI-Collaborative Development Workflow

This workflow assumes that system design, STM32CubeMX configuration, and project generation have already been completed. It consists of six basic steps.

**（1）Confirm the Initial Project State**
Confirm that the current project compiles normally, and treat this state as the baseline for subsequent modifications.

**（2）Analyze the Project with Claude Code**
Have Claude Code read the `.ioc` file, initialization code, and related source files to understand the project conditions required for the task, providing a basis for subsequent task planning and code review.

**（3）Create a Task List Based on the Analysis**
Ask Claude Code to generate a code implementation task list based on the functional goals. Tasks should be split by complete functionality, with each task's objective, files involved, and main modification locations described.

**（4）Modify Code Task by Task**
Select one task at a time and ask Claude Code to generate the corresponding code changes. After review, confirmation, and functional validation, proceed to the next task.

**（5）Review and Confirm Code Changes**
The developer reviews the changes generated by Claude Code, confirms whether the modified files, code locations, and implemented functionality match the current task, and then decides whether to accept them or request regeneration.

**（6）Compile, Flash, and Verify by Running**
After accepting the changes, recompile the project, flash it to the board, and verify whether the functionality meets the task requirements through actual runtime results. If verification fails, the error information can be fed back to Claude Code for analysis.

The above steps can be summarized into three basic principles: **base every modification on evidence, review every modification, and verify every modification.**

## 6. Quick Start

（1） **Clone this repository**
       git clone https://github.com/youcans/AI4MCU-STM32G4-Prompt.git

（2） **Enter the experiment project directory**
   Using the basic peripheral experiment `GPIO_EXTI` as an example:
       cd nucleo-g431rb_basics/GPIO_EXTI

   This directory already contains the two basic input files required for the experiment:
       GPIO_EXTI.ioc
       requirements.txt

（3） **Generate the initial project with STM32CubeMX**
   Double-click `GPIO_EXTI.ioc` to open it with STM32CubeMX. After checking the configuration, click **GENERATE CODE** to generate the initial project.

（4） **Confirm the initial project state**
   Open the project directory in VS Code, wait for CMake to configure automatically, then click **Build** to compile. Confirm that the initial project compiles normally, and treat this state as the baseline for subsequent modifications.

（5）  **Start AI-collaborative development**
   Once the initial project is confirmed, follow the [AI-Collaborative Development Workflow](#4-ai-collaborative-development-workflow) section to complete project analysis, task planning, code modification, and verification in sequence.
