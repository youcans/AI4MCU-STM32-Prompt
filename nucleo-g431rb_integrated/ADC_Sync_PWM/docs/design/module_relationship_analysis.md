> 说明：本文档分析模块之间的控制关系、事件流和数据流，识别潜在问题。不展开备选方案、模块接口、函数、变量、数据结构和代码实现。

---

## 1. 模块关系类型

模块之间存在三种关系：

| 关系类型 | 含义 | 示例 |
|---|---|---|
| **控制/调用** | 模块 A 在自身执行上下文中调用模块 B 的接口 | MD-04 调用 MD-01 启动实时链路 |
| **事件通知** | 模块 A 在事件发生时通知模块 B，由 B 决定如何处理 | MD-02 通知 MD-04：注入组序列完成 |
| **数据依赖** | 模块 A 读取模块 B 持有的数据 | MD-04 读取 MD-03 持有的 DAC 输出值 |

## 2. 模块间关系总览

### 2.1 控制/调用关系

```
┌──────────┐    传递注入组采样值    ┌──────────┐
│  MD-02   │ ───────────────────► │  MD-03   │
│ 采样管理  │                      │ 实时处理  │
└────┬─────┘                      └────┬─────┘
     │                                 │
     │ 通知 JEOS / 传递温度值           │ PWM 占空比
     │                                 │
     │           ┌──────────┐          │
     └──────────►│  MD-04   │          │
                 │ 系统控制  │          │
                 └────┬─────┘          │
                      │                │
                      │ 触发串口发送     │
                      │                │
                      ▼                │
                 ┌──────────┐          │
                 │  MD-05   │          │
                 │ 串口监测  │          │
                 └────┬─────┘          │
                      │                │
                      │ 启动 DMA       │
                      │                │
                      ▼                ▼
                 ┌──────────────────────────┐
                 │         MD-01            │
                 │        板级支持           │
                 │                          │
                 │ 统一执行：ADC 注入组子流程  │
                 │ TIM1 和 PWM 启停；DAC 写入 │
                 │ GPIO 翻转；DMA 启动       │
                 └──────────────────────────┘
```

**调用方向**（A → B 表示 A 调用 B）：

| 调用方 | 被调用方 | 调用场景 | 执行上下文 |
|---|---|---|---|
| MD-02 | MD-03 | 注入组序列完成后传递采样值 | ADC1_2 中断（注入组完成分支） |
| MD-02 | MD-04 | 通知注入组完成（LED 翻转）；规则组完成后传递温度值 | ADC1_2 中断 |
| MD-03 | MD-01 | 写入 TIM1 比较寄存器（PWM 占空比更新） | ADC1_2 中断（被 MD-02 调用链中） |
| MD-04 | MD-01 | 启动/停止实时链路（统一执行 ADC 注入组、TIM1 和 PWM 启停）；DAC 写入；GPIO 翻转；初始化 | TIM6 更新中断 / EXTI13 事件 / 初始化 |
| MD-04 | MD-05 | 根据 SystemState 选择数据源（DAC 输出值或芯片温度值），传递给 MD-05 组帧发送；异常状态下不触发 | TIM6 更新中断 |
| MD-05 | MD-01 | 启动 DMA 发送 | TIM6 更新中断（被 MD-04 调用链中） |

**关键设计决策**：MD-01 统一执行 ADC 注入组、TIM1 和 PWM 的底层启停。MD-04 通过调用 MD-01 的实时链路启停操作来控制整个实时路径的启停。MD-02 不参与硬件启停，仅负责 ADC 转换完成事件的处理、采样数据读取与分发。MD-05 不读取 `SystemState`——由 MD-04 根据 `SystemState` 选择数据源后传递给 MD-05，消除 MD-05 对 MD-04 的数据反向依赖。

调用关系（全部单向，无数据反向依赖）：
```
MD-02 → MD-03 → MD-01
MD-02 → MD-04 → MD-01
MD-04 → MD-05 → MD-01
```

### 2.2 事件通知关系

```
 硬件中断源                         模块入口                       最终处理
─────────────                     ──────────                    ──────────

TIM1 触发 ─────────────────────► ADC1 注入组（硬件自动触发）

ADC1_2 中断 ────► MD-02 ────┬────► MD-03（传递采样值，调用）
                            │
                            ├────► MD-04（注入组完成通知：LED 翻转）
                            │
                            └────► MD-04（规则组完成：传递温度值，温度判断）

EXTI13 事件 ─────────────────────► MD-04（按键事件：状态切换）

TIM6 更新中断 ───────────────────► MD-04（500 Hz 调度：
                                      DAC 翻转、LED 分频、
                                      根据 SystemState 触发 MD-05 串口发送）

TIM6_TRGO ──────────────────► ADC1 规则组（硬件自动触发）

DMA 发送完成 ────────────────────► MD-05（清除发送忙状态，允许下次发送）
```

**说明**：
- TIM1 触发和 TIM6_TRGO 为硬件内部连接，不经过任何软件模块。
- ADC1_2 中断为一个中断入口。MD-02 在此中断中区分注入组序列完成和规则组转换完成两类事件，分别读取对应的转换结果，并分发给 MD-03 和 MD-04。
- TIM6 更新事件同时产生 TRGO（硬件触发 ADC 规则组）和中断请求（进入 MD-04）。ADC 规则组在 TRGO 触发后开始转换，其转换完成事件与 TIM6 中断处理之间的实际执行顺序取决于 ADC 采样时间和中断优先级——两者之间不存在确定的先后关系。
- MD-04 接收两类独立事件源：EXTI13 事件（按键）和 TIM6 更新中断（500 Hz 调度），以及两类来自 MD-02 的软件通知（注入组完成、温度值传递）。

---

### 2.3 数据依赖关系

| 数据 | 生产者（持有者） | 消费者（读取者） | 读取场景 |
|---|---|---|---|
| 注入组采样值（三路） | MD-02（ADC 读取） | MD-03 | ADC1_2 中断（注入组完成分支）中，由 MD-02 传入 |
| PWM 占空比（第一组） | MD-03（计算产出） | MD-01（写 TIM1 比较寄存器） | ADC1_2 中断中，MD-03 调用 MD-01 写入 |
| DAC 输出值 | MD-03（计算、暂存） | MD-04（DAC 翻转、运行状态串口数据源） | TIM6 更新中断中读取 |
| 芯片温度值 | MD-02（ADC 读取、换算） | MD-04（温度判断、停止状态串口数据源） | ADC1_2 中断（规则组完成分支）中（MD-04 温度判断）；TIM6 更新中断中（MD-04 读取用于串口发送） |
| `SystemState` | MD-04（独占修改） | MD-04 自身（内部决策） | MD-04 在状态切换和周期调度中读取 |
| 第二/三组 PWM 预设值 | 开发者配置 | MD-04 → MD-01 | 初始化时写入 TIM1 比较寄存器 |
| 温度异常阈值 / 恢复阈值 | 开发者配置 | MD-04 | 温度判断时读取 |

**说明**：
- MD-01 不持有任何业务数据，仅通过寄存器操作将数据写入硬件。
- MD-02 不需要读取 `SystemState`——注入组采样仅在运行状态下由硬件触发（TIM1 运行），非运行状态下注入组不会产生完成事件，因此 MD-02 无需通过 `SystemState` 判断是否处理。
- 注入组采样值为瞬时传递（MD-02 → MD-03 直接传参），不暂存于 MD-02。
- DAC 输出值和芯片温度值为持存数据：MD-03 和 MD-02 分别持有，对外提供只读访问。
- `SystemState` 由 MD-04 独占修改并在内部使用，其他模块不读取 `SystemState`。MD-02 和 MD-03 的执行由硬件事件驱动（注入组仅在 TIM1 运行时触发）；MD-05 接收 MD-04 已选定的数据，无需自行判断状态。

## 3. 主要事件分析

### 3.1 10 kHz 实时路径事件

| 事件 | 来源 | 接收方 | 处理流程 | 用途 |
|---|---|---|---|---|
| TIM1 周期事件 | TIM1 硬件 | ADC1 注入组（硬件自动） | TIM1 触发 ADC1 注入组按序转换 | 建立 PWM 与 ADC 采样的相位同步 |
| 注入组序列完成 | ADC1 硬件 → ADC1_2 中断 → MD-02 | MD-02 → MD-03、MD-04 | MD-02 读取三路注入组结果 → MD-03 计算 → MD-03 调用 MD-01 写 TIM1 比较寄存器；MD-02 通知 MD-04（LED 翻转） | 驱动 10 kHz 实时处理：采样 → 计算 → PWM 更新 |

**时序要求**：从 ADC1_2 中断进入到 TIM1 比较寄存器更新完成须远小于 100 µs（设计约束）。

---

### 3.2 500 Hz 周期事件

| 事件 | 来源 | 接收方 | 处理流程 | 用途 |
|---|---|---|---|---|
| TIM6_TRGO | TIM6 硬件 | ADC1 规则组（硬件自动） | TIM6 更新事件输出 TRGO 信号，触发 ADC1 规则组转换通道 16（内部温度传感器） | 500 Hz 温度采样触发 |
| 规则组转换完成 | ADC1 硬件 → ADC1_2 中断 → MD-02 | MD-02 → MD-04 | MD-02 读取规则组结果 → 换算为芯片温度值 → 传递给 MD-04 | MD-04 执行温度异常判断 |
| TIM6 更新中断 | TIM6 硬件 | MD-04 | MD-04 依次执行：DAC 翻转 → LED 分频计数 → 根据 SystemState 触发 MD-05 | 500 Hz 周期调度 |

**时序说明**：TIM6_TRGO 与 TIM6 更新中断均由同一 TIM6 更新事件产生。TRGO 硬件触发 ADC 规则组开始转换；中断请求同时进入 MD-04 开始 500 Hz 调度。规则组转换完成（触发 ADC1_2 中断）与 TIM6 更新中断处理之间无确定的先后关系——取决于 ADC 采样时间和中断优先级配置。温度判断始终在规则组转换完成后执行，与 TIM6 更新中断的执行时序无关。

---

### 3.3 异步事件

| 事件 | 来源 | 接收方 | 处理流程 | 用途 |
|---|---|---|---|---|
| 用户按键事件 | EXTI13 硬件 | MD-04 | MD-04 读取当前 SystemState，执行状态切换（停止↔运行） | 用户控制运行/停止 |
| 温度异常进入 | MD-04 内部产出 | MD-04 | 温度判断检测到超过异常阈值 → 状态机转入异常 | 自动保护 |
| 温度异常退出 | MD-04 内部产出 | MD-04 | 温度判断检测到低于恢复阈值 → 状态机从异常返回停止 | 自动恢复 |
| 串口 DMA 发送完成 | LPUART1/DMA 硬件 | MD-05 | MD-05 清除发送忙状态，允许后续周期启动新的 DMA 发送 | 确保 500 Hz 发送周期不重叠 |

## 4. 关键数据流分析

### 4.1 同步采样与 PWM 更新数据流（10 kHz）

```
ADC1 注入组三通道：
  Rank1: PA1 (动态模拟电压)  ←── 参与 PWM 和 DAC 计算
  Rank2: PB1 (高电平参考)    ←── 暂不参与动态计算
  Rank3: PB0 (低电平参考)    ←── 暂不参与动态计算
    │
    ▼
ADC1 注入组按 Rank1→2→3 顺序转换
    │
    ▼
MD-02 读取三路注入组结果
    │
    ├──► MD-03 计算（当前仅使用 PA1 采样值）
    │         │
    │         ├──► PwmDutyCh1 ──► MD-01 写 TIM1 CCR1 ──► TIM1 CH1/CH1N PWM 输出
    │         │
    │         └──► DacOutputValue（MD-03 暂存，10 kHz 更新）
    │
    └──► MD-04（注入组完成通知 → 运行状态下 LED 翻转）
```

**说明**：此数据流在每次注入组序列完成事件中执行一次（10 kHz）。PwmDutyCh1 在 ADC1_2 中断中通过 MD-01 写入 TIM1 比较寄存器，更新后续 PWM 周期的占空比。DacOutputValue 仅暂存，不在本路径中写入 DAC。

---

### 4.2 DAC 输出数据流（500 Hz）

```
MD-03 持有的 DacOutputValue（10 kHz 更新）
    │
    ▼
MD-04 在 TIM6 更新中断中读取
    │
    ├──► 当前为"高"半周期 → MD-01 写入 DAC = DacOutputValue
    │
    └──► 当前为"低"半周期 → MD-01 写入 DAC = 0

DAC1_OUT1 (PA4) ──► 250 Hz 方波输出
```

**说明**：DAC 寄存器写入仅在 TIM6 更新中断中发生（500 Hz），每次翻转一次（值 ↔ 0），形成 250 Hz 方波。MD-04 在每次 500 Hz 周期事件中读取最近一次完成更新的 DAC 输出值。

---

### 4.3 温度监测数据流（500 Hz）

```
ADC1_IN16 (内部温度传感器)
    │
    ▼
ADC1 规则组转换 ──► ADC1_2 中断（规则组完成分支）
    │
    ▼
MD-02 读取规则组结果、换算为芯片温度值
    │
    └──► MD-04
              │
              ├── 温度异常判断
              │     ├── 超过异常阈值 → TemperatureFaultEnter → 状态机 → 转入异常
              │     └── 低于恢复阈值 → TemperatureFaultExit → 状态机 → 返回停止
              │
              └── 停止状态下 500 Hz 调度时：将芯片温度值传递给 MD-05 组帧发送
```

**说明**：温度采样由 TIM6_TRGO 硬件触发，转换完成后在 ADC1_2 中断中处理。温度判断在获得有效芯片温度值后执行，与 TIM6 更新中断的执行时序无关。停止状态下温度采样和判断持续运行（TIM6 全状态运行）。首次规则组转换完成后，芯片温度值在停止状态下持续更新并保持有效。首次有效温度值产生之前，不应发送该数据。

---

### 4.4 系统状态广播数据流

```
MD-04 状态机
    │
    │ 输入事件:
    ├── UserButtonEvent（EXTI13 事件）──► 停止 ↔ 运行
    ├── TemperatureFaultEnter ──────────► 任意状态 → 异常
    └── TemperatureFaultExit ───────────► 异常 → 停止

    │ 输出: SystemState（MD-04 内部使用）
    ▼
    MD-04 自身根据 SystemState 决定：
    ├── PWM 启停、DAC 启停、LED 行为 → 调用 MD-01 执行
    └── 串口数据源选择（运行→DAC 值，停止→温度值，异常→不发送）→ 调用 MD-05
```

**说明**：`SystemState` 由 MD-04 独占修改，仅在 MD-04 内部使用。其他模块不读取 `SystemState`：MD-01 仅接收 MD-04 的明确启停命令；MD-05 接收 MD-04 已选定的数据；MD-02 和 MD-03 的执行由硬件事件驱动。

---

### 4.5 串口发送数据流（500 Hz，运行/停止状态）

```
MD-04 TIM6 更新中断
    │
    ├── 异常状态 → 不触发 MD-05
    │
    └── 运行或停止状态 → 根据 SystemState 选择数据源：
            │
            ├── 运行: 读取 MD-03 的 DacOutputValue
            └── 停止: 读取 MD-02 的芯片温度值
            │
            ▼
        将选定的数据传递给 MD-05
            │
            ▼
        MD-05 JustFloat 组帧（8 字节）
            │
            ▼
        MD-01 启动 DMA 发送
            │
            ▼
        LPUART1/DMA 传输
            │
            ▼
        DMA 发送完成事件
            │
            ▼
        MD-05 清除发送忙状态
```

**说明**：MD-04 根据 `SystemState` 选择数据源并传递给 MD-05；MD-05 仅负责组帧和 DMA 发送，不读取 `SystemState` 也不直接从 MD-02 或 MD-03 读取数据。该设计消除了 MD-05 对 MD-04 的数据反向依赖。

---

## 5. 潜在问题与待确认事项

### 5.1 中断服务例程入口归属

**问题**：MD-02 处理 ADC1_2 中断，MD-04 处理 TIM6 更新中断和 EXTI13 事件。HAL 库生成的中断服务例程入口函数需放置在某个文件中，该文件的归属需要明确。

**待确认**：各中断入口函数集中放置在一个独立的中断管理文件，还是分别放在对应模块中？

---

### 5.2 MD-02 注入组完成事件和规则组完成事件的区分方式

**问题**：ADC1_2 中断为一个中断入口，注入组序列完成和规则组转换完成均通过此中断上报。MD-02 需要在中断中区分两类事件并分别处理。

**待确认**：MD-02 通过 HAL 的不同回调区分两类事件，还是通过检查 ADC 状态寄存器中的标志位自行区分？

---

### 5.3 MD-05 的 DMA 完成处理

**问题**：MD-05 通过 MD-01 启动 DMA 发送，并需维护 DMA 发送忙状态以避免重复启动。DMA 传输完成后需清除忙标志。

**待确认**：DMA 传输完成后的标志清除由 MD-05 自行处理（在 DMA 中断回调中），还是由 MD-01 统一处理后通知 MD-05？

---

### 5.4 初始化顺序

**问题**：系统初始化由 MD-04 调度，各模块初始化存在顺序依赖：MD-01 必须先完成外设底层初始化，MD-02 的 ADC 中断配置和 MD-04 的 TIM6/EXTI13 中断配置才能进行。

**待确认**：初始化顺序是否需要显式文档约束？

---

### 5.5 MD-04 职责集中度

**问题**：MD-04 系统控制模块承担了最多的事件入口和调度职责：两个硬件事件源（EXTI13、TIM6）、来自 MD-02 的两类软件通知、内部状态机、三个 500 Hz 周期任务调度（DAC 翻转、LED 分频、串口触发）、温度异常判断和初始化调度。

**待确认**：当前职责集合在单个源文件中实现是否可接受？是否需要考虑在详细设计中将 500 Hz 调度子逻辑与状态机逻辑在文件内部做结构分离？

---

### 5.6 芯片温度值在停止状态下的有效性

**确认**：停止状态下 TIM6 继续运行，TIM6_TRGO 持续触发 ADC 规则组转换，MD-02 持续在 ADC1_2 中断中读取和换算温度值。首次规则组转换完成后，芯片温度值在停止状态下持续更新并保持有效。首次有效温度值产生之前，MD-04 不应触发停止状态下的串口发送。

---

### 5.7 模块设计文档待同步更新

**提示**：本次分析中已确认 MD-02 的职责收窄——不负责 ADC 硬件启停，仅负责 ADC 转换完成处理与采样数据管理。MD-01 统一执行 ADC 注入组、TIM1 和 PWM 的底层启停。`docs/design/module_design.md` 中 MD-01 和 MD-02 的职责描述需同步更新以保持一致。

---

以上分析不涉及模块接口、函数、变量、数据结构和代码实现。标注为"待确认"的事项需在后续设计阶段明确。
