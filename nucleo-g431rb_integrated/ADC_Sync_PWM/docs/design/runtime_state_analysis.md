> 编制日期：2026-08-05
> 依据文件：

> - `docs/design/module_design.md`（软件模块设计）

> 说明：本文档基于已确认的软件功能、模块划分和模块关系，梳理系统的主要运行流程、状态切换条件和切换后的行为。不重新设计软件架构，不展开接口、函数、变量和代码实现。

---

## 1. 运行流程总览

系统存在三条并发的运行流程，分别由不同的硬件事件驱动：

| 流程 | 触发事件 | 频率 | 有效状态 | 参与模块 |
|---|---|---|---|---|
| 同步采样与 PWM 更新 | TIM1 周期事件 → ADC1 注入组完成 | 10 kHz | 运行 | MD-02、MD-03、MD-04（LED 翻转）、MD-01 |
| 500 Hz 周期处理（软件调度） | TIM6 更新中断 | 500 Hz | 全状态 | MD-04、MD-01、MD-05（运行/停止） |
| 500 Hz 温度采样与判断（硬件触发） | TIM6_TRGO → ADC1 规则组完成 | 500 Hz | 全状态 | MD-02、MD-04 |
| 异步事件处理 | EXTI13、温度异常事件、DMA 发送完成 | 不定 | 视事件类型 | MD-04、MD-05 |

---

## 2. 同步采样与 PWM 更新流程（10 kHz，仅运行状态）

**触发事件**：TIM1 周期事件

**参与模块**：MD-02（采样管理）、MD-03（实时处理）、MD-04（系统控制，LED 翻转）、MD-01（板级支持）

**主要处理步骤**：

```
TIM1 周期事件（硬件）
    │
    ▼
ADC1 注入组按 Rank1(PA1)→2(PB1)→3(PB0) 顺序转换（硬件自动）
    │
    ▼
ADC1_2 中断（注入组完成分支）→ MD-02
    │
    ├── (1) MD-02 读取三路注入组转换结果
    │
    ├── (2) MD-02 → MD-03：传递采样值
    │         │
    │         ▼
    │    MD-03 计算 PwmDutyCh1 和 DacOutputValue
    │         │
    │         ├── PwmDutyCh1 → MD-01 写 TIM1 CCR1（更新后续 PWM 周期占空比）
    │         └── DacOutputValue → MD-03 暂存（10 kHz 更新）
    │
    └── (3) MD-02 → MD-04：通知注入组完成
              │
              ▼
         MD-04：运行状态下翻转 LED（通过 MD-01）
```

**处理结果**：
- TIM1 CH1/CH1N 占空比更新（PwmDutyCh1），CH2/CH3 保持预设值
- DacOutputValue 更新（MD-03 暂存，不在本流程中写入 DAC）
- LED 翻转一次（10 kHz 翻转，肉眼观察近似常亮）

**时序约束**：从 ADC1_2 中断进入到 TIM1 CCR 更新完成须远小于 100 µs。

**状态依赖**：仅在运行状态下 TIM1 运行，注入组被触发并产生完成事件。停止和异常状态下 TIM1 停止，本流程不执行。

## 3. 500 Hz 周期处理流程（全状态）

500 Hz 周期涉及两条并发的子流程，均由 TIM6 驱动但在不同时刻执行：

### 3.1 软件调度子流程（TIM6 更新中断）

**触发事件**：TIM6 更新中断

**参与模块**：MD-04（系统控制）、MD-01（板级支持）、MD-05（串口监测，运行/停止状态）

**主要处理步骤**：

```
TIM6 更新中断 → MD-04
    │
    ├── (1) DAC 翻转：
    │        读取 MD-03 持有的 DacOutputValue
    │        交替写入 DacOutputValue 或 0 → MD-01 写 DAC 寄存器
    │        运行状态：形成 250 Hz 方波
    │        停止/异常状态：MD-01 关闭 DAC 输出
    │
    ├── (2) LED 分频计数：
    │        异常状态：每 25 个事件翻转 LED（10 Hz 闪烁）
    │        停止/运行状态：LED 由其他路径控制（见第 2 节和第 5 节）
    │
    └── (3) 串口发送调度：
              ├── 运行状态：MD-04 读取 MD-03 的 DacOutputValue → 传递给 MD-05 组帧发送
              ├── 停止状态：芯片温度值有效时，MD-04 读取 MD-02 的芯片温度值 → 传递给 MD-05 组帧发送
              │           （首次规则组温度转换完成前，芯片温度值无效，不触发发送）
              └── 异常状态：不触发 MD-05
```

**处理结果**：
- 运行状态：DAC 输出 250 Hz 方波；串口发送 DacOutputValue
- 停止状态：DAC 关闭；串口发送芯片温度值
- 异常状态：DAC 关闭；串口不发送；LED 10 Hz 闪烁

---

### 3.2 温度采样与判断子流程（硬件触发，异步于 TIM6 中断）

**触发事件**：TIM6_TRGO → ADC1 规则组转换完成

**参与模块**：MD-02（采样管理）、MD-04（系统控制）

**主要处理步骤**：

```
TIM6 更新事件
    │
    ├── TRGO → ADC1 规则组开始转换通道 16（硬件自动）
    │
    └── TIM6 更新中断（见 3.1 节，与本流程并行）

ADC1 规则组转换完成 → ADC1_2 中断（规则组完成分支）→ MD-02
    │
    ├── (1) MD-02 读取规则组转换结果
    │
    ├── (2) MD-02 换算为芯片温度值（本模块持有，对外只读）
    │
    └── (3) MD-02 → MD-04：传递芯片温度值
              │
              ▼
         MD-04 温度异常判断：
              ├── 超过异常阈值 → 产生 TemperatureFaultEnter → 状态机
              └── 低于恢复阈值 → 产生 TemperatureFaultExit → 状态机
```

**处理结果**：
- 芯片温度值更新（MD-02 持有）
- 首次规则组转换完成后，芯片温度值标记为有效（后续停止状态下串口发送的前置条件）
- 温度异常进入/退出事件（如有）

**时序说明**：TIM6_TRGO 和 TIM6 更新中断由同一 TIM6 更新事件产生。规则组转换完成（触发 ADC1_2 中断）与 3.1 节的软件调度（TIM6 更新中断）之间无确定的先后关系——取决于 ADC 采样时间和中断优先级配置。温度判断始终在规则组转换完成后执行，与 TIM6 更新中断的执行时序无关。

上电后首个 TIM6 更新事件同时启动第一次温度采样（TRGO）和第一次 TIM6 更新中断调度。由于 ADC 转换需要时间，首次 TIM6 更新中断中软件调度的串口发送可能早于首次温度转换完成。因此，停止状态下的串口发送须以"芯片温度值有效"为前置条件：首次规则组转换完成前不触发温度数据发送，获得首个有效温度值后才开始周期发送。

**状态依赖**：全状态执行（TIM6 在所有状态下持续运行）。

## 4. 异步事件处理流程

### 4.1 用户按键事件

**触发事件**：EXTI13 事件（PC13 上升沿）

**参与模块**：MD-04（系统控制）

**主要处理步骤**：

```
EXTI13 事件 → MD-04
    │
    ├── 当前为停止状态 → SystemState 切换为运行
    │         │
    │         ├── MD-04 → MD-01：启动实时链路
    │         │     （MD-01 统一执行：先使能 ADC 注入组，再启动 TIM1 和 PWM 输出）
    │         │
    │         └── MD-04 → MD-01：启动 DAC 输出
    │
    ├── 当前为运行状态 → SystemState 切换为停止
    │         │
    │         ├── MD-04 → MD-01：停止实时链路
    │         │     （MD-01 统一执行：先停止 TIM1 触发源，再停止注入组采样并关闭 PWM 输出）
    │         │
    │         └── MD-04 → MD-01：DAC 置零并关闭输出
    │
    └── 当前为异常状态 → 不响应
```

**处理结果**：停止 ↔ 运行状态切换，PWM、ADC 注入组、DAC 输出随状态启停。

---

### 4.2 温度异常进入事件

**触发事件**：TemperatureFaultEnter（MD-04 内部产出，在温度判断中产生）

**触发条件**：仅在停止或运行状态下，芯片温度值 ≥ TemperatureFaultThreshold 时产生。异常状态下不产生此事件（只检查恢复条件）。

**参与模块**：MD-04（系统控制）

**主要处理步骤**：

```
MD-04 温度判断（停止或运行状态下）：
    芯片温度值 ≥ TemperatureFaultThreshold
    │
    ▼
TemperatureFaultEnter
    │
    ▼
SystemState → 异常
    │
    ├── MD-04 → MD-01：停止实时链路（关闭 PWM 和 ADC 注入组）
    │
    └── MD-04 → MD-01：DAC 置零并关闭输出
```

**处理结果**：系统进入异常状态，PWM 和 DAC 关闭，温度采样和判断继续运行（仅检查恢复），LED 以 10 Hz 闪烁，串口停止发送。

---

### 4.3 温度异常退出事件

**触发事件**：TemperatureFaultExit（MD-04 内部产出，在温度判断中产生）

**参与模块**：MD-04（系统控制）

**主要处理步骤**：

```
MD-04 温度判断：芯片温度值 ≤ TemperatureRecoveryThreshold（且当前为异常状态）
    │
    ▼
TemperatureFaultExit
    │
    ▼
SystemState → 停止
    │
    └── PWM、ADC 注入组、DAC 保持关闭状态（与停止状态一致）
```

**处理结果**：系统从异常返回停止状态。返回后需用户再次按键才能进入运行状态。

---

### 4.4 串口 DMA 发送完成事件

**触发事件**：LPUART1 DMA 传输完成

**参与模块**：MD-05（串口监测）

**主要处理步骤**：

```
DMA 发送完成 → MD-05
    │
    └── 清除发送忙状态，允许后续 500 Hz 周期启动新的 DMA 发送
```

**处理结果**：发送忙标志清除，下一周期可正常启动发送。

## 5. 系统状态切换

### 5.1 状态切换条件

```
                    上电/复位
                       │
                       ▼
                  ┌─────────┐
                  │  停止    │
                  └────┬────┘
                       │
            ┌──────────┼──────────┐
            │ 按键      │ 温度异常  │
            ▼          ▼          │
       ┌─────────┐ ┌─────────┐   │
       │  运行    │ │  异常    │   │
       └────┬────┘ └────┬────┘   │
            │           │         │
            │ 按键       │ 温度恢复 │
            ▼           ▼         │
       ┌─────────┐      │         │
       │  停止    │◄─────┘         │
       └─────────┘                │
            ▲                     │
            └─────────────────────┘
              (另一路径：停止→温度异常→异常)

状态切换规则：
  - 停止 → 运行：用户按键（EXTI13）
  - 运行 → 停止：用户按键（EXTI13）
  - 停止 → 异常：温度异常进入（TemperatureFaultEnter），仅停止状态下产生
  - 运行 → 异常：温度异常进入（TemperatureFaultEnter），仅运行状态下产生
  - 异常 → 停止：温度异常退出（TemperatureFaultExit），仅异常状态下产生
  - 异常状态下：按键不产生状态切换；仅检查温度恢复条件，不产生温度异常进入事件
```

### 5.2 各状态下的系统行为

| 行为项 | 停止 | 运行 | 异常 |
|---|---|---|---|
| TIM1 / PWM 输出 | 关闭 | 开启（10 kHz，三组带死区互补） | 关闭 |
| ADC1 注入组采样 | 停止 | 执行（10 kHz，三通道） | 停止 |
| 实时数据处理（SF-05） | 不执行 | 执行（10 kHz） | 不执行 |
| DAC 输出 | 关闭 | 开启（250 Hz 方波） | 关闭 |
| 芯片温度采样（SF-07） | 执行（500 Hz） | 执行（500 Hz） | 执行（500 Hz） |
| 温度异常判断（SF-08） | 执行 | 执行 | 执行（判断恢复） |
| LED 指示 | 熄灭 | 每次注入组完成翻转（近似常亮） | 10 Hz 闪烁 |
| 串口发送 | 发送芯片温度值（500 Hz） | 发送 DAC 输出值（500 Hz） | 不发送 |
| 按键响应 | 响应（→运行） | 响应（→停止） | 不响应 |
| 温度异常响应 | 响应（→异常） | 响应（→异常） | 仅检查恢复，不产生异常进入 |
| 温度恢复响应 | — | — | 响应（→停止） |

### 5.3 状态切换时的模块动作

| 状态切换 | MD-04 动作 | MD-01 执行 |
|---|---|---|
| 停止 → 运行 | ① 更新 SystemState → 运行；② 调用 MD-01 启动实时链路；③ 调用 MD-01 启动 DAC 输出 | ① 先使能 ADC 注入组，再启动 TIM1 和 PWM 输出；② 使能 DAC 输出 |
| 运行 → 停止 | ① 更新 SystemState → 停止；② 调用 MD-01 停止实时链路；③ 调用 MD-01 将 DAC 置零并关闭输出 | ① 先停止 TIM1 触发源，再停止注入组采样并关闭 PWM 输出；② DAC 置零并关闭输出 |
| 停止或运行 → 异常 | ① 更新 SystemState → 异常；② 调用 MD-01 停止实时链路（如当前为运行状态）；③ 调用 MD-01 将 DAC 置零并关闭输出 | 同运行→停止的动作 |
| 异常 → 停止 | ① 更新 SystemState → 停止；② 不触发实时链路和 DAC 动作（已在异常状态时关闭） | 无硬件启停动作 |
