## 1. 验证目标

完整验证温度异常进入（STOP/RUN → FAULT）和恢复（FAULT → STOP）的硬件现象和状态转换。T06 已确认温度采样链路正常，T07 已确认三状态状态机和 FAULT 保护逻辑正常（已用真实加热完成初步验证），T08 已验证串口监测，本任务在完整系统上通过实际温度变化对全链路进行正式验证。

## 3. 验证项目和操作步骤

### 3.1 停止状态 → 异常（STOP → FAULT）

| 步骤 | 操作 | 预期现象 |
|---|---|---|
| 1 | 上电，确认系统处于停止状态 | LED 熄灭，VOFA+ 收到温度数据（约 33°C） |
| 2 | 用电吹风对 MCU 加热 | VOFA+ 显示温度逐步上升 |
| 3 | 温度 > 45°C | LED 变为 10 Hz 闪烁，VOFA+ 停止收到数据（串口不再发送） |
| 4 | 按 B1 | 无响应，LED 仍为 10 Hz 闪烁，状态保持 FAULT |

**通过判据**：温度 > 45°C 时自动进入 FAULT（LED 10 Hz 闪烁、串口停止），FAULT 状态下按键不响应。实时链路本已关闭（STOP 状态），无 PWM/DAC 变化。

### 3.2 运行状态 → 异常（RUN → FAULT）

| 步骤 | 操作 | 预期现象 |
|---|---|---|
| 1 | 确保系统处于停止状态（上一步 FAULT 后等待温度降至 40°C 以下自动恢复 STOP，再进行本项验证） | LED 熄灭 |
| 2 | 按 B1 进入运行状态 | LED 常亮，PA4 250 Hz 方波，PA8 10 kHz PWM，VOFA+ 显示 DAC 幅值 |
| 3 | 用电吹风对 MCU 加热 | 旋转电位器时 DAC 幅值和 PWM 占空比仍随之变化。通过 LED 在加热过程中是否变为闪烁判断温度是否超过阈值 |
| 4 | 温度 > 45°C | LED 变为 10 Hz 闪烁；示波器确认 PA4 输出关闭、PA8/PB13 PWM 关闭；VOFA+ 停止收到数据 |
| 5 | 按 B1 | 无响应，状态保持 FAULT |

**通过判据**：运行状态温度 > 45°C 时自动进入 FAULT，PWM/DAC 全部关闭，串口停止，按键不响应。

### 3.3 异常 → 停止（FAULT → STOP，恢复）

| 步骤 | 操作 | 预期现象 |
|---|---|---|
| 1 | 在 FAULT 状态下（LED 10 Hz 闪烁）停止加热 | 等待芯片自然降温 |
| 2 | 观察恢复（FAULT 期间串口停发，以 LED 熄灭、串口重新发送为判断依据） | LED 熄灭（进入 STOP）；VOFA+ 重新收到温度数据，记录恢复后首先显示的温度值（应 < 40°C） |
| 3 | 按 B1 | LED 常亮，PWM/DAC 恢复输出，VOFA+ 切换为 DAC 幅值 |

**通过判据**：LED 熄灭（FAULT→STOP）且 VOFA+ 重新收到温度数据，恢复后首先显示的温度值 < 40°C；返回 STOP 后可通过按键再次进入运行。

## 4. 异常记录要求

若验证过程中发现以下异常，应记录相关现象和数据：

| 异常类型 | 记录内容 |
|---|---|
| 温度阈值偏差 | 记录触发 FAULT 时串口停止前最后的 VOFA+ 温度值，以及恢复 STOP 后 VOFA+ 首先显示的温度值，对比设定阈值 |
| 状态转换异常 | 记录转换前后的 LED 状态、PWM/DAC 开关状态、串口数据变化 |
| 按键异常 | 记录 FAULT 状态下按 B1 是否有响应 |
| 恢复异常 | 记录 FAULT → STOP 后 LED 是否熄灭，按键是否能重新进入运行 |

T07 实现状态机时已用真实加热完成了异常进入（>45°C）和恢复（<40°C）的初步验证；T08 已验证三种状态下的串口数据源切换。本任务按任务清单 T09 对温度异常保护和状态转换进行正式、完整的板级验证：覆盖 STOP→FAULT、RUN→FAULT（含 PWM/DAC 关闭确认）、FAULT→STOP 恢复及恢复后重新进入运行的全过程，并按 §4 记录阈值触发时的实际温度数据。

## 8. 编译、调试和板级验证方法

- **编译/烧录**：使用 T08 已验证固件烧录（本任务无代码变更，无需重新编译）。
- **调试/观测**：按 §3 的步骤执行——目视 LED（熄灭/常亮/10 Hz 闪烁）、示波器（PA4 250 Hz 方波、PA8/PB13 10 kHz PWM）、VOFA+（JustFloat、115200 bps，温度/DAC 幅值数据）；
- 温度阈值触发时机：进入 FAULT 时记录串口停止前最后的温度值；恢复 STOP 以 LED 熄灭、串口重新发送为判断依据，并记录恢复后 VOFA+ 首先显示的温度值。

## 9. 实施顺序建议

2. 按 §3.1 → §3.2 → §3.3 顺序执行三项验证；
3. 按 §4 记录异常（如有）；
4. 将验证结果记录至 `docs/logs/task_log.md`，待批准后进入 T10。

## 10. 风险与注意事项

| 事项 | 说明 |
|---|---|
| 加热控制 | 使用低温档热风，避免过热损坏芯片；加热期间持续观察 VOFA+ 温度值 |
| 降温时间 | 停止加热后芯片自然降温至 40°C 以下需要时间，耐心等待并观察 VOFA+ 温度 |
| 阈值判读 | FAULT 期间串口停发、无法连续观察温度：进入 FAULT 记录串口停止前最后的温度值，恢复 STOP 以 LED 熄灭和串口恢复为判断依据，并记录恢复后首个温度值 |
| 任务清单备注 | 若难以创造温度变化条件，此项验证可延后（任务清单 T09 已注明） |
