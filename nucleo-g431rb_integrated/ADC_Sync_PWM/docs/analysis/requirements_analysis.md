### 1.2 事件关系与数据流向

依据原文描述，各功能要素之间的主要事件触发关系和数据流向如下：

```text
PWM周期事件（来自 FT-01）
    │
    ├── 触发 ──→ 多通道ADC采样（FT-02）──→ 原始采样值
    │                                            │
    │                                            ▼
    │                                    实时数据处理（FT-03）
    │                                    （读取、转换、
    │                                     确定更新时机）
    │                                            │
    │                    ┌───────────────────────┼───────────────────────┐
    │                    ▼                       ▼                       ▼
    │              PWM占空比更新            DAC输出更新            串口波形发送
    │              （FT-01 的一部分）       （FT-04）               （FT-08）
    │
    └── （PWM 定时基准持续运行，产生下一周期事件）

芯片温度监测（FT-05）
    │
    └── 温度超限？──→ 温度异常处理（FT-09）
                        │
                        ├──→ 系统状态？（待确认）
                        └──→ LED 指示？（待确认）
```

关键数据链路：

- **采样链路**：PWM 周期事件 → ADC 多通道采样 → 原始采样值
- **处理链路**：原始采样值 → 实时数据处理（读取、转换）→ 处理结果
- **控制链路**：处理结果 → PWM 占空比更新
- **模拟输出链路**：处理结果 → DAC 输出更新
- **波形链路**：处理结果 → 串口数据帧封装 → 上位机波形显示
- **监测链路**：芯片温度采集 → 阈值比较 → 温度异常处理 → ？（响应动作待确认）

以下关系原文未明确，标记为**待确认**：

- 芯片温度的采集通道和触发方式；
- 温度异常后的具体响应动作（是否影响系统状态、是否触发 LED 指示）；
- 系统状态的具体切换条件和各状态下的行为差异；
- LED 指示与系统状态、温度异常之间的具体对应关系。

| 功能职责维度 | 原文涉及情况 | 原文依据 |

| 输出控制 | 涉及 | PWM 占空比更新；DAC 输出更新 |

## 3. 隐含功能确认检查

以下原文用语隐含了需要进一步明确的功能边界：

| "多通道" | 具体使用几个 ADC 通道？各通道的采样对象分别是什么？是否所有通道均参与占空比计算？温度监测是否占用独立通道？ | FT-02 |

- "监测"隐含了"异常判断 + 异常响应"职责，该职责在原文中未展开，据此单独识别出候选主题 FT-09（温度异常处理）。

## 5. 主题合并说明

| 原要素 | 处理结果 | 处理理由 |

## 7. 总结

从仅 9 行的初始要求原文中，共提取出 **9 个候选功能主题**：

| 来源类型 | 主题 |
|---|---|
| 原文直接提出 | FT-02（ADC 采样）、FT-04（DAC 输出）、FT-05（温度监测）、FT-06（状态切换）、FT-07（LED 指示）、FT-08（串口波形） |
| 由事件关系拆分得到 | FT-01（PWM 输出与占空比控制） |
| 由数据处理职责拆分得到 | FT-03（实时数据处理） |
| 由隐含功能检查推导增加 | FT-09（温度异常处理） |

全部 9 个主题均存在不同程度待确认的细节，共标记 **15 项待确认事项**。

FT-03（实时数据处理）作为 FT-02（ADC 采样）与 FT-01（PWM 更新）、FT-04（DAC 更新）、FT-08（串口发送）之间的数据处理中枢，是项目实时调度链路的核心环节。FT-09（温度异常处理）补充了原文"监测"需求隐含但未展开的异常处理职责。

各候选功能主题与七个功能职责维度的对应关系如下：

| 功能职责维度 | 对应候选功能主题 |
|---|---|
| 数据采集 | FT-02、FT-05 |
| 数据处理 | FT-03 |
| 输出控制 | FT-01、FT-04 |
| 输出显示 | FT-07、FT-08 |
| 状态控制 | FT-06 |
| 异常处理 | FT-09 |
| 数据通信 | FT-08 |

七个维度均有对应主题，无维度空缺。FT-08（串口波形数据发送）同时归属"输出显示"和"数据通信"两个维度，因其既承担波形数据的对外呈现职责，也承担串口通信职责，二者在本阶段不作进一步拆分。
